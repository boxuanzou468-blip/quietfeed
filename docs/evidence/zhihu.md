# 知乎适配证据与边界

日期：2026-10-22。状态：**试验适配，推荐区域待登录实测**。

## 真实公开页面探测

使用项目安装的 Chromium，在新的无登录浏览器 context 中只读访问以下页面。没有使用用户试用 profile，没有登录、发送验证码或处理验证挑战，没有保存网页正文或账号信息。

| 目标                                      | 本次可观察结果                                                           | 可以证明的范围                               |
| ----------------------------------------- | ------------------------------------------------------------------------ | -------------------------------------------- |
| `https://www.zhihu.com/`                  | HTTP 200，原站跳转至 `/signin?next=%2F`，标题“知乎 - 有问题，就会有答案” | 真实登录入口存在；不能证明登录后的推荐区结构 |
| `https://www.zhihu.com/question/19551415` | HTTP 403，错误码 `40362`，原站提示访问异常                               | 本次未取得问题/回答 DOM                      |
| `https://zhuanlan.zhihu.com/p/56998402`   | HTTP 403，错误码 `40362`                                                 | 本次未取得专栏正文 DOM；该域名不纳入权限     |

Codex 内置浏览器对首页的独立检查同样停留在原站登录页。网页检索工具亦未能访问公开推荐页。后续一次 Chromium 重试还遇到连接被关闭。这些结果均不算推荐隐藏成功。

登录页可观察到的命名结构包括 `.SignFlow`、`.SignContainer-content`、`.signQr-container` 和 `.SignFlowHomepage`；适配器保留登录相关路由，并对前三种结构提供保护。实际登录输入、提交和验证码均未操作。

## 当前实现

仅申请 `https://www.zhihu.com/*`。每站独立启用，新增站点默认关闭。

| 模块       | 页面范围                                         | 精确候选选择器                                                                         | 证据状态                                           |
| ---------- | ------------------------------------------------ | -------------------------------------------------------------------------------------- | -------------------------------------------------- |
| `homeFeed` | `/`，且不是明确选择其他 tab 的查询参数           | `.Topstory-recommend .TopstoryItem`                                                    | 保守候选；仅合成页面通过，未验证登录后真实推荐 DOM |
| `related`  | `/question/数字` 或 `/question/数字/answer/数字` | `.Question-sideColumn .RelatedQuestions`、`.Question-sideColumn .QuestionRelatedTopic` | 保守候选；仅合成页面通过，未验证当前真实问题 DOM   |

推荐候选选择器使用有明确语义的模块名，只在固定页面类型中生效。它们是实现假设，不是本轮真实 DOM 成功证据。未命中时保持页面可见并交由扩展的模块状态显示适配异常；不扩大至 `.Card`、整个侧栏、整个正文或应用根节点。首页引导仅在确实匹配到可隐藏推荐卡片时出现。

不实现热榜侧栏、默认热搜、专栏推荐、视频、商业推广等额外模块。保留 `/follow`、`/hot`、`/search`、个人主页、收藏、消息和登录/验证路由；问题页仅处理已命名的相关模块，保护问题标题、正文、回答和评论。通用卡片内的 `.RichContent` 仍可属于首页推荐，因此正文保护按 `.Question-mainColumn` 限定，避免反过来让所有推荐卡片无法收起。

## 合成测试

`tests/fixtures/zhihu-*.html` 全部为独立编写的最小合成结构；文本、问题和回答均为占位文案，没有从真实用户页面复制内容。类名用于检验适配器的安全边界，不是脱敏的真实页面快照。

`tests/zhihu.test.ts` 验证推荐隐藏/完整恢复、搜索焦点与输入保留、问题/回答/评论保留、相关模块独立开关、关注/搜索/登录跳转恢复、嵌套登录和验证结构保护、未知布局保留、专栏域名保留，以及放行与动态卡片。上述测试不能替代真实知乎验收。

## 仍需人工验收

- 用户自行完成原站登录后，在 Chrome 和 Edge 各验证首页推荐是否匹配；不提供验证码给开发者。
- 进入关注页、搜索结果页和个人主页，确认正常内容保留。
- 从原站可访问的问题进入问题/回答页，确认仅相关模块被收起，回答、评论和收藏正常。
- 对比开关、模块设置、10 分钟放行、多标签页与撤销网站授权后的恢复。
- 如果当前推荐 DOM 已改版，先提交不含账号或正文的结构证据，再调整明确模块；不以宽泛隐藏掩盖失配。
